از نام دامنه تا پاسخ سرور: DNS را درست بشناسیم

با دانستن نقش resolver و TTL، تفاوت «دامنه حل نمی‌شود» با «سرور جواب نمی‌دهد» روشن می‌شود.

بازبینی محتوایی: شهریور ۱۴۰۵ · زمان مطالعه: حدود ۶ دقیقه

DNS نشانی را پیدا می‌کند، نه سلامت وب‌سایت را

مرورگر معمولاً برای تبدیل نامی مانند example.org به نشانی IP از resolver استفاده می‌کند. resolver ممکن است پاسخ را از کش داشته باشد یا برای به‌دست آوردن آن با سرورهای نام مناسب ارتباط بگیرد. رکورد A نشانی IPv4 و AAAA نشانی IPv6 را گزارش می‌کند؛ این رکوردها تضمین نمی‌کنند که برنامهٔ روی سرور اجرا می‌شود.

ممکن است DNS درست به IP برسد ولی اتصال TCP به پورت ۴۴۳ رد شود؛ یا اتصال برقرار شود ولی گواهی TLS مشکل داشته باشد. این رخدادها باید جداگانه سنجیده شوند.

TTL و تغییرات DNS

TTL مدت زمانی است که پاسخ DNS می‌تواند در کش نگهداری شود. هنگام تغییر نشانی IP، بعضی resolverها تا پایان TTL پاسخ قبلی را استفاده می‌کنند؛ کش مرورگر و سیستم‌عامل نیز می‌توانند در رفتار مشاهده‌شده نقش داشته باشند.

برای آزمایش دقیق، خروجی resolver معمول و یک resolver دیگر را مقایسه کنید؛ اما نتیجهٔ یک resolver را به کل اینترنت تعمیم ندهید. در CDN ممکن است پاسخ IPهای لبه را نشان دهد و دیگر IP واقعی Origin در نتیجهٔ عمومی پیدا نباشد.

روش عیب‌یابی لایه‌به‌لایه

ابتدا رکورد DNS را بررسی کنید. سپس مشخص کنید آیا TCP به پورت هدف وصل می‌شود، آیا TLS با نام صحیح مذاکره می‌کند، و در نهایت HTTP چه کد پاسخی می‌دهد. خطاهای ۴۰۴، ۵۰۲ و ۵۰۴ هر کدام مرحلهٔ متفاوتی را نشان می‌دهند.

اگر سایت از CDN استفاده می‌کند، آزمایش مستقیم Origin باید نام میزبان و SNI اصلی را حفظ کند؛ جایگزین کردن سادهٔ دامنه با IP ممکن است به صفحه یا گواهی دیگری برسد.
