چرا تصویر و صفحهٔ قدیمی هنوز نمایش داده می‌شود؟

کش مرورگر و CDN مفید است، اما انتشار نادرست می‌تواند فایل جدید را پشت نسخهٔ قبلی پنهان کند.

بازبینی محتوایی: شهریور ۱۴۰۵ · زمان مطالعه: حدود ۶ دقیقه

دو سوءبرداشت دربارهٔ کش

no-cache به معنای ممنوعیت ذخیره‌سازی نیست؛ یعنی قبل از استفادهٔ دوباره باید اعتبار نسخه بررسی شود. no-store ذخیره را منع می‌کند. برای HTML عمومی که ممکن است تغییر کند، اعتبارسنجی معمولاً بهتر از ممنوع کردن بی‌هدف همهٔ کش‌هاست.

هدرهای ETag و Last-Modified امکان پاسخ ۳۰۴ را فراهم می‌کنند تا اگر منبع تغییر نکرده، محتوای کامل دوباره ارسال نشود. وجود یا نبود این هدرها را باید همراه با سیاست Cache-Control دید.

فایل‌های ثابت را نسخه‌دار کنید

اگر نام فایل CSS همیشه site.css باقی بماند، بعضی کش‌ها ممکن است نسخهٔ قدیمی را نگه دارند. الگوی قابل اطمینان این است که هنگام تغییر محتوا نام فایل یا شناسهٔ نسخهٔ آن عوض شود؛ برای منابع واقعاً تغییرناپذیر می‌توان زمان کش طولانی تعیین کرد.

برای HTML، یک سیاست بازاعتبارسنجی روشن و برای CSS و تصویرهای نسخه‌دار سیاست کش متناسب انتخاب کنید. تغییر دادن همهٔ سیاست‌ها به no-store معمولاً هزینهٔ دانلود را بالا می‌برد.

روش انتشار مرحله‌ای

فایل‌های جدید را اول در مسیر درست قرار دهید، صحت URLها را بررسی کنید، سپس HTML را به نسخهٔ جدید ارجاع دهید. پس از انتشار، همان URLها را هم از مسیر Origin و هم از مسیر CDN آزمایش کنید.

اگر تغییر فوری لازم است، پاک‌سازی کش URL مشخص در پنل CDN ممکن است لازم شود. این کار با Ctrl+F5 مرورگر فرق دارد.
